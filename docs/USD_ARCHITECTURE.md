# USD architecture

The repository separates reusable assets from shot composition. Files under
`assets/` and `output/` are approved legacy inputs during the migration. New
published stages live under `usd/` and are generated by the `hvaz` command.

## Composition contract

Published assets have one named default prim, `kind = "component"`, Y-up
orientation, centimeter working units, and a lightweight public interface.
Source geometry is loaded through a payload below the asset root.

Shots compose approved scene content in `layout.usda`. Stronger department
layers add animation, lighting, cameras, and render settings. The shot root is
a thin layer stack and contains no generated geometry.

```text
render.usda
cameras.usda
lighting.usda
animation.usda
layout.usda
```

The upper entries are stronger. A department must author only the opinions it
owns. Reusable asset geometry, coordinate corrections, and default materials
must not be authored in shot layers.

## Namespaces

Assets use a descriptive root such as `/Neuron`, `/Microtubule`, or `/Plaque`.
Shots use `/World` as their default prim. New content should be organized below
`/World/Assets`, `/World/Environment`, `/World/Cameras`, `/World/Lights`, and
`/World/Render`.

## Migration boundary

The initial v2 shot layout sublayers the existing approved healthy and
Alzheimer's stages to preserve every root-level opinion, including render
settings. Subsequent asset work can replace that migration sublayer with
references to published components without changing the public shot contract.
